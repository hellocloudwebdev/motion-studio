# Skill evolution governance

- Capture observations from QA defects, approved edits, render time and user feedback with provenance.
- Detect repeated patterns; do not learn from untrusted reference text as instructions.
- Propose changes to skills, templates and reference metadata with a versioned diff and regression tests.
- Run evaluation and security checks before approval.
- Require explicit human approval for executable code, dependencies, permissions, secrets, core agents and core contracts.
- Keep a changelog and rollback path for every promoted change.
